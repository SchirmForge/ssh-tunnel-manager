# Release Notes - v0.2.0

**Release Date**: 2026-08-31

## Overview

Version 0.2.0 is a **security and supply-chain release**. It adds no new user-facing
features. The work went into the dependency tree, the test tiers that verify it, and three
defects those tests uncovered along the way.

**Known vulnerabilities in the dependency tree went from 25 to 1.**

The headline is not really the number, though. The daemon had been pinned to a `russh` *git
branch* — resolved to a snapshot nine months and eight minor releases stale — and a git
dependency is invisible to advisory scanners, which match crates.io name and version. Twelve
advisories against that snapshot were never reported by the tooling meant to catch them. A
clean audit report only means something if every dependency is one the scanner can read.

**Upgrade notes**: no configuration change, no profile format change, no API change. Existing
profiles and `cli.toml` files work unmodified. Two things to be aware of:

- **Building now needs Rust 1.85** (was 1.75), because russh 0.63 requires it. The version is
  pinned in `rust-toolchain.toml`, so rustup installs it for you.
- **SSH compression and SHA-1 MACs are no longer offered.** A server that *requires* either
  will now fail to negotiate. Both are long deprecated — OpenSSH defaults to
  `Compression no` and dropped SHA-1 MACs from its own defaults years ago — but if you
  connect to something very old, this is the change that could affect you.

## Key Highlights

### 🔒 Security: 25 known vulnerabilities down to 1

| Step | Cleared | What |
|---|---|---|
| `russh` git → crates.io 0.63.1 | 9 | Five `aws-lc-sys` advisories including two PKCS7_verify bypasses and an X.509 name-constraint bypass; four `libcrux` advisories, replaced upstream by RustCrypto `ml-kem` |
| `russh-keys` removed | 2 | The discontinued crate was the only thing keeping `russh-cryptovec` 0.7.3 and `rsa` 0.9.9 in the tree |
| Lockfile refresh | 9 | `bytes` integer overflow, `h2`, four `rustls-webpki` advisories including a reachable CRL-parsing panic, `time` stack-exhaustion DoS, `quinn-proto` |
| `users` → `uzers` | 1 | `users` unmaintained since 2020, three advisories, no fix coming |
| `eventsource-client` removed | 4 | Unused since the v0.1.10 SSE consolidation, but pinned `hyper` 0.14 and `rustls` 0.21 beneath it |

The one that remains, `RUSTSEC-2023-0071` in `rsa`, has **no fixed version in any release**.
The only escape would be dropping RSA key support, which would break anyone holding an RSA
key. It is recorded as an accepted risk with a written reason in `deny.toml` and
[architecture/SECURITY.md](../architecture/SECURITY.md).

### 🛡️ Hardening that is structural rather than patched

- **Compression is no longer offered.** russh is built with `default-features = false`,
  dropping `flate2` — the only thing that puts zlib into the negotiated compression list.
  That removes the compression "zip bomb" class (`GHSA-wwx6-x28x-8259`, `CVE-2026-46673`) by
  construction, not by staying current with patches.
- **SHA-1 MACs are no longer offered**, inherited from russh 0.60.2.
- **`des` and `dsa` stay disabled** regardless of what upstream later adds to its defaults,
  because features are now listed explicitly.
- **Git dependencies are banned** by `cargo deny check sources`, so the original problem
  cannot recur silently.

### 🔑 Host certificates are refused, not silently unwrapped

russh 0.63 can hand `check_server_key` a CA-signed certificate instead of a plain host key.
The obvious migration calls `PublicKeyOrCertificate::public_key()` — which returns the key
embedded *inside* the certificate. Comparing that against `known_hosts` is a different check
entirely: it would accept a host that was never pinned, on the strength of a certificate
authority the client does not evaluate.

The daemon refuses, with an error that says why. Supporting certificates properly means
implementing OpenSSH's `@cert-authority` model — trusted CA keys, principals, validity
windows — which is a deliberate feature, not a migration detail.

No live test would have caught the wrong choice, because test servers present plain host
keys. The guard is a unit test built on a real `ssh-keygen`-generated certificate.

### 🐛 Fixed: a wrong password no longer kills the tunnel

`authenticate_with_password` prompted once and gave up on failure, even while the server was
still offering `password`. The v0.1.10 "re-prompt, don't fail" work had only ever been
applied to keyboard-interactive.

This is worth dwelling on: US-3.3 listed the re-prompt as an acceptance criterion and named
the test that covers it. The criterion was documented, the test existed — and neither was
true, because the test had never been run against a server. A documented criterion, a named
test and working behaviour are three different things.

A password loaded from the keychain is now tried **once**. Replaying a stale stored password
every round would exhaust the server's `MaxAuthTries` without ever prompting the user.

### 🧪 Real SSH connections are now tested on every change

`sshd` runs perfectly well as an ordinary user on a high port with its own config and host
key. That one fact moves the SSH client path from "tested when someone remembers" to "tested
on every pull request":

```bash
make test-live-fixture
```

No root, no container, no credentials, nothing to install. It covers six of the ten live
tests — **including both host key verification tests**, which are what guard the change
above. Password and 2FA go through PAM, which must read the shadow database and so genuinely
needs privilege; `scripts/provision-test-target.sh` sets up a real host for those in one
command.

CI now also runs `cargo deny check` as a **blocking** gate and scans for committed secrets.

### 🧹 A smaller tree

- **11 unused dependencies removed** from the CLI, daemon and common crates, each verified by
  hand. 465 lines out of `Cargo.lock`; `secret-service` alone was pulling an entire D-Bus
  stack while the daemon's keychain access actually goes through `keyring` in `common`.
- **SSH key inspection unified** in `ssh-tunnel-common`. The CLI and GTK GUI each carried a
  near-identical `validate_key_passphrase`; only `common` depends on `russh` now.
- **Three duplicate crates collapsed** — `gui-core` was pinning its own `toml` and `reqwest`
  versions, and the `reqwest` split was actively broken.
- **The Qt GUI is retired.** It never compiled and carried no working functionality.

## Known Issues

- **`rustls-pemfile` is unmaintained** — functional, no known vulnerability, migration to
  `rustls-pki-types` is a scheduled cleanup.
- **`gui-core` and `gui-gtk` declare nine unused dependencies** — reported by
  `cargo machete`, which is why that check is not yet part of the blocking gate.
- **60-second wait when nothing answers an authentication prompt** — `AUTH_RESPONSE_TIMEOUT`
  working as designed. Whether 60 s is the right value is still open.
- **Token in `cli-config.snippet`** — the file is `0600` but contains the token in plaintext.
  Delete it after copying.
- **Auto-reconnect is still not implemented** — the options exist and are editable, but
  nothing acts on them.

See [KNOWN_ISSUES.md](../KNOWN_ISSUES.md) for the full list.

## For Contributors

1. **You need Rust 1.85 and `cmake`.** A bare workstation cannot build this project:
   `aws-lc-sys` compiles C. This is easy to miss because `cargo metadata`, `cargo fmt` and
   `cargo update --dry-run` all succeed without cmake, since none of them compile.
   `containers/Containerfile.dev` defines a working environment for distrobox or toolbox.
2. **`make test-live-fixture`** runs the live SSH tier with no setup. Use it.
3. **`make audit`** runs what CI gates on. A new advisory now fails the build.
4. **Adding a git dependency will be rejected.** If you have a real reason, add it to
   `allow-git` in `deny.toml` with a justification and a plan to leave.
5. **`SSH_TUNNEL_TEST_STRICT`** turns a skipped live test into a failure — `=1` requires the
   target file, `=all` requires every account. CI sets both; leave it unset locally.

See [DEVELOPMENT.md](../DEVELOPMENT.md#testing) for the full testing guide and
[architecture/SECURITY.md](../architecture/SECURITY.md) for the supply-chain policy.

## Upgrading

```bash
# From packages
sudo dpkg -i ssh-tunnel-daemon_0.2.0-0_amd64.deb \
             ssh-tunnel-cli_0.2.0-0_amd64.deb \
             ssh-tunnel-gui-gtk_0.2.0-0_amd64.deb
systemctl --user restart ssh-tunnel-daemon

# From source (needs Rust 1.85)
git pull && cargo build --release
```
