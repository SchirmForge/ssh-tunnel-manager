# Release Notes - v0.6.0

**Release Date**: 2026-09-03

## Overview

The second-generation GTK 4/libadwaita interface is now the production desktop application.
It is installed and launched as `ssh-tunnel-gui`; the earlier `ssh-tunnel-gtk` source remains
in the workspace only as an obsolete, frozen compatibility reference.

This release also makes editing a profile safe while its tunnel is active. Saving never
silently changes or interrupts the running tunnel: the GUI explains when the previous
settings are still in use and lets the user keep that connection or reconnect immediately.

There is no daemon wire-API or profile-format change, and existing `cli.toml`, `ui.toml`,
profiles, and stored credentials continue to work.

## Key Highlights

### Production desktop GUI

- `crates/gui-v2` is the default root-workspace GUI package and builds the
  `ssh-tunnel-gui` executable.
- The application ID is `io.github.schirmforge.SshTunnelManager`.
- The Makefile, development environment, installer, CI, and desktop entry use the production
  identity.
- `crates/gui-gtk` remains compilable on the same GTK 4.22/libadwaita 1.9 binding generation,
  but it is not a default, installed, or packaged target and receives no updates.

### Edit an active profile safely

Profiles remain editable while connecting, awaiting authentication, connected, or
reconnecting. After a successful save, the GUI states that the current tunnel still uses the
previous settings and offers two explicit choices:

- **OK** leaves the current connection running. The saved settings apply the next time it
  connects.
- **Reconnect now** stops the current tunnel and starts it with the saved profile.

The reconnect path is shared in `gui-core` so a future presentation adapter can dispatch the
same typed action. It uses the existing tunnel stop, status, and start endpoints, and waits for
a structured inactive status before starting again.

This is a user-requested reconnect after editing. It does not implement automatic reconnect
after a network failure, and it does not add an API for starting or restarting the daemon
process.

### Authentication prompt presentation

Daemon-supplied authentication copy now uses the semantic window background instead of a
contrasting card background. It remains unparsed display text: request and status codes alone
select controls and actions.

## Security and correctness

- The decision to show the post-save notice comes from `TunnelStatus`, not from a daemon
  message.
- Stop/start sequencing polls the structured tunnel-status response and has a bounded wait.
- A failed profile save never offers reconnect.
- Existing credential Keep/Store/Remove behavior and request-correlated authentication are
  unchanged.

## Validation

- GUI core: 53 unit tests passed.
- Production GUI: 26 unit tests passed.
- Default workspace: 214 tests passed, 19 live/environment tests ignored, 0 failed.
- Strict Clippy passed for `gui-core` and `gui-v2`.
- Both GUI crates compile in the controlled Fedora 44 environment. The obsolete GUI retains
  its known libadwaita deprecation warnings.
- Dependency bans, licenses, and sources passed policy checks; existing duplicate-version
  findings remain warnings.
- Formatting and whitespace checks passed.

## Known limitations

- Automatic SSH tunnel reconnect and health monitoring remain unimplemented.
- Tray implementation and tray-library selection remain deferred.
- Stored TOTP generation, SSH config import, new per-tunnel telemetry, and daemon-process
  lifecycle APIs remain deferred.
- The production GUI is currently validated only on Bazzite/Fedora 44.
- Keyboard-only and screen-comparison review remain follow-up validation.

See [KNOWN_ISSUES.md](../KNOWN_ISSUES.md) and [ROADMAP.md](../ROADMAP.md) for the complete
current status.

## Upgrading

No configuration migration is required. Current source installs use:

```bash
cargo build --release
sudo install -Dm755 target/release/ssh-tunnel-gui /usr/local/bin/ssh-tunnel-gui
```

If upgrading from a package that installed `ssh-tunnel-gtk`, use the new
`ssh-tunnel-gui` launcher after installing the v0.6.0 GUI package.
