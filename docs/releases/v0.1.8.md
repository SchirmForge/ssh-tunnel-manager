# SSH Tunnel Manager - v0.1.8 Release

**Release Date**: 2025-12-26
**Status**: First Public Release - Production Ready for Local Port Forwarding

## Overview

SSH Tunnel Manager is a comprehensive SSH tunnel management application for Linux with three components:
- **Daemon** - Background service managing SSH connections
- **CLI** - Command-line interface for tunnel control
- **GUI** - Modern GTK4/Libadwaita graphical interface

This first release provides a stable foundation for managing SSH local port forwarding tunnels with interactive authentication, real-time status updates, and comprehensive security features.

## What Works

### ✅ Core Functionality

**SSH Tunnel Management**
- ✅ Local port forwarding (`ssh -L`) fully implemented
- ✅ Interactive authentication (password, SSH key passphrase, keyboard-interactive/2FA)
- ✅ SSH host key verification with OpenSSH-compatible known_hosts
- ✅ Real-time connection status via Server-Sent Events (SSE)
- ✅ Profile-based configuration with TOML persistence
- ✅ System keyring integration for credential storage

**Daemon**
- ✅ Three operational modes: Unix socket (default), TCP HTTP (localhost), TCP HTTPS (network)
- ✅ Token-based authentication (enabled by default)
- ✅ Self-signed TLS certificate generation with fingerprint pinning
- ✅ Graceful shutdown with proper cleanup
- ✅ PID file locking prevents duplicate instances
- ✅ REST API and SSE endpoint for tunnel control
- ✅ Daemon info API (`/api/daemon/info`) with comprehensive metadata
- ✅ Graceful daemon shutdown via API

**CLI**
- ✅ Profile management (add, list, show, delete, info)
- ✅ Tunnel control (start, stop, restart, status)
- ✅ Batch operations (stop --all, status --all)
- ✅ Interactive prompts and non-interactive flags
- ✅ Daemon introspection (info, dump-config commands)
- ✅ Proactive config validation with helpful error messages
- ✅ Interactive daemon config snippet copy
- ✅ Color-coded output and formatted tables
- ✅ JSON output mode for scripting

**GUI**
- ✅ Modern Libadwaita/GTK4 interface
- ✅ Two-page navigation (Client profiles and Daemon status)
- ✅ Full profile CRUD (create, edit, delete)
- ✅ Real-time status indicators (colored dots: green/orange/red/gray)
- ✅ Daemon connection monitoring with auto-reconnect
- ✅ Authentication dialogs for interactive prompts
- ✅ Comprehensive daemon status page with real-time info
- ✅ Client configuration viewer (read-only)
- ✅ Help and About dialogs with markdown rendering
- ✅ Advanced tunnel options (compression, keepalive, packet sizes)

**Security**
- ✅ Authentication enabled by default for all modes
- ✅ HTTP mode restricted to loopback addresses only
- ✅ Network access requires HTTPS with certificate pinning
- ✅ File permissions hardening (0600 for sensitive files)
- ✅ Restrictive umask (0077) prevents permission leaks
- ✅ SSH host key verification prevents MITM attacks
- ✅ Credentials stored in OS keyring (not on disk)
- ✅ Optional group access mode for shared daemons

**Headless/Server Support**
- ✅ Graceful keyring fallback when unavailable
- ✅ `SSH_TUNNEL_SKIP_KEYRING` environment variable
- ✅ Profile creation succeeds without keyring
- ✅ Comprehensive systemd integration documentation

## Known Limitations & Missing Features

### ❌ Not Yet Implemented

**Tunnel Types**
- ❌ Remote port forwarding (`ssh -R`) - Planned for v0.2.0
- ❌ Dynamic/SOCKS proxy (`ssh -D`) - Planned for v0.2.0
- ❌ Auto-reconnect/health monitoring - Config exists but not wired
  - Options present in profile configuration but not implemented
  - Manual restart required when connections drop

**GUI Features**
- ❌ System tray integration - No background GUI mode yet
- ❌ Desktop notifications - `notify-rust` dependency present but unused
- ❌ Dark mode auto-selection - Currently follows system theme but no manual toggle
- ❌ Daemon autostart configuration via GUI - Must use systemctl manually
- ❌ Profile autostart configuration - Not implemented

**CLI Features**
- ❌ No automatic log rotation for daemon logs
- ❌ Configurable daemon config path - Currently hardcoded to `~/.config/ssh-tunnel-manager/daemon.toml`
- ❌ No structured logging (JSON) option

**Authentication**
- ❌ Remote host password storage - Only SSH key passphrase is stored
  - Keyboard-interactive and password auth require manual entry each time
  - Only SSH key passphrases can be stored in keyring

**System Integration**
- ❌ Limited package formats available - Only .deb packages for now
  - RPM and possibly other packages planned for future releases
- ❌ No autostart on login (systemd user service exists but manual setup required)

### Quick Start

```bash
# Start the daemon (if not using systemd)
ssh-tunnel-daemon &

# Or start the daemon with systemd
systemctl start --user ssh-tunnel-daemon

# Create a profile (see additional options or use the gui for a more complex setup)
ssh-tunnel add myserver \
  --host example.com \
  --user myuser \
  --key ~/.ssh/id_ed25519 \
  --local-port 8080 \
  --remote-host localhost \
  --remote-port 80

# Start the tunnel
ssh-tunnel start myserver

# Check status
ssh-tunnel status myserver

# Or use the GUI
ssh-tunnel-gui
```

## Security Considerations

### Default Security Posture

✅ **Secure by Default**
- Authentication required for all daemon modes
- HTTP mode restricted to localhost only
- Network access requires HTTPS + certificate pinning
- All sensitive files created with 0600 permissions
- Umask set to 0077 to prevent permission leaks

### Recommended Setup

For **local-only use** (most secure):
```toml
# daemon.toml
listener_mode = "unix-socket"  # Default
require_auth = true            # Default
```

For **network use** (e.g., remote GUI):
```toml
# daemon.toml
listener_mode = "tcp-https"
require_auth = true
bind_host = "0.0.0.0"
bind_port = 3443
```

⚠️ **Never use HTTP mode over network** - It's restricted to loopback for security reasons.

### Threat Model

**Protected Against**
✅ MITM attacks (TLS certificate pinning in HTTPS mode)
✅ Unauthorized daemon access (token authentication)
✅ SSH host key spoofing (known_hosts verification)
✅ Credential theft from disk (keyring storage)
✅ Permission leaks (restrictive umask and file permissions)

**Not Protected Against**
⚠️ Malicious processes running as the same user (by design - Unix permission model)
  - Any process running as your user can access your Unix socket and config files
  - This is the intended Unix security model - we trust processes running as the same user
⚠️ Keyloggers or memory dumping (credentials in memory during use)
⚠️ Compromised SSH servers on first connect (host key verification trusts first connection)

## Troubleshooting

### Daemon won't start
```bash
# Check if already running
ps aux | grep ssh-tunnel-daemon

# Check PID file
cat /run/user/$(id -u)/ssh-tunnel-manager/daemon.pid

# Remove stale PID file if needed
rm /run/user/$(id -u)/ssh-tunnel-manager/daemon.pid
```

### GUI shows "Daemon Disconnected"
```bash
# Check daemon status
systemctl --user status ssh-tunnel-daemon

# View daemon logs
journalctl --user -u ssh-tunnel-daemon -f

# Restart daemon
systemctl --user restart ssh-tunnel-daemon
```

### Authentication failures (401 errors)
```bash
# Validate config
ssh-tunnel dump-config

# Copy daemon config snippet (if missing)
ssh-tunnel start <profile>  # Will prompt to copy snippet

# Check auth token matches
cat ~/.config/ssh-tunnel-manager/daemon.token
grep auth_token ~/.config/ssh-tunnel-manager/cli.toml
```

### Keyring unavailable on headless server
```bash
# Skip keyring for this session
export SSH_TUNNEL_SKIP_KEYRING=1

# Or permanently configure profile without keyring
ssh-tunnel add myserver --host example.com --user myuser --key ~/.ssh/id_ed25519
# When prompted for passphrase, leave empty if key is unencrypted
```
