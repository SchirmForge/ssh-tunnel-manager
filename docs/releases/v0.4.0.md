# Release Notes - v0.4.0

**Release Date**: 2026-09-01

## Overview

Version 0.4.0 delivers the source implementation and automated validation baseline for the
second-generation GTK 4/libadwaita interface. It also turns `gui-core` into a genuinely
toolkit-neutral application layer instead of a collection of helpers tied to the outgoing
GTK implementation.

This is deliberately a **preview release of GUI v2**, not the production cutover. The
packaged GUI and default root-workspace target remain `ssh-tunnel-gtk`. GUI v2 is currently
the isolated `ssh-tunnel-gui-v2` executable and targets the GTK/libadwaita stack supplied by
Bazzite/Fedora 44.

There is no daemon API or profile-format migration. GUI-only state is stored in a new,
separate `ui.toml` beside `cli.toml` and the profile directory.

## Highlights

### Secure first-launch client setup

GUI v2 now performs first-launch client setup before constructing its daemon runtime. It can
import the daemon-generated snippet, request a usable network host, collect manual Unix
socket/HTTP/HTTPS settings, and repair an invalid configuration. Missing, malformed, and
incomplete configuration remains in a recoverable setup state rather than starting a runtime
with unsafe defaults.

Setup decisions use parsed local configuration, connection-mode variants, and typed field
errors—not daemon prompt or status strings. The daemon API token stays in the atomically
installed `0600` `cli.toml`; profile passwords and passphrases remain separate in the common
Secret Service/keyutils credential facade. The wizard configures a client connection to an
existing daemon and does not start or restart the daemon process.

### A reusable application core

`gui-core` now owns immutable application snapshots, typed commands/effects, action
availability, feature capabilities, profile editor state, authentication queueing, GUI
preferences, and runtime effect execution. GTK widgets only render snapshots and dispatch
commands. The same profile commands can later be exposed by a tray adapter without copying
daemon or profile logic.

### Profile organization and editing

GUI v2 provides search, connected-only filtering, name/manual sorting, pinning, drag
ordering, keyboard ordering, profile details, and create/edit/duplicate/delete workflows.
Presentation preferences are versioned and saved atomically in:

```text
${XDG_CONFIG_HOME:-~/.config}/ssh-tunnel-manager/ui.toml
```

Profile TOML remains authoritative for connection behavior. Existing credentials are never
loaded into editor text state; saves use redacted Keep/Store/Remove operations with rollback
on failure. Local SSH key paths are validated on the client, while daemon-host paths are not
mistaken for local files.

### Structured authentication control

Authentication requests are queued FIFO and keyed by the exact daemon request ID. Typed
request variants choose password, key-passphrase, keyboard-interactive, two-factor, and
host-key presentation. The structured `hidden` flag chooses input visibility.

Daemon strings are displayed but never parsed or matched to choose behavior. Misleading or
localized words such as “password”, “connected”, or “accept” cannot enable controls or change
the answer type. Unknown or contradictory codes fail closed.

### Honest WIP states

Controls without a backend operation are visibly marked **WIP**. Authentication type, 2FA,
account/password, and auto-reconnect selections still reveal and validate their real local
fields, but unsupported persistence/runtime actions cannot report success. Remote and
dynamic forwarding values are preserved rather than silently converted to local forwarding.

### Accessibility and responsive layout

The source includes keyboard shortcuts, keyboard-accessible reordering, labelled icon
buttons and form controls, alert/status semantics, focus/default actions, wrapping action
groups, and scrollable long-content surfaces. Styling uses system fonts and semantic
GTK/libadwaita colors.

Automated/source checks are complete. Runtime keyboard traversal, Orca announcements, high
contrast, enlarged system fonts, narrow resizing, localized copy, and visual comparison are
still pending manual validation.

- Root workspace: 168 passed, 18 live/environment-dependent tests ignored, 0 failed.

## Not included in v0.4.0

| Item | Disposition |
|---|---|
| Tray implementation and tray-library selection | Deferred. Shared profile commands are ready; no adapter or dependency has been selected. |
| Stored TOTP generation or secret persistence | Deferred. Keyboard-interactive/structured two-factor prompts work, but no TOTP seed is stored or generated. |
| Daemon API for starting/restarting the daemon | Deferred. Health/info/refresh are real; lifecycle controls remain WIP. |
| SSH config import | Deferred. The visible entry point is WIP and does not open a picker or claim success. |
| New traffic, uptime, or last-connected telemetry | Deferred. Existing daemon-wide uptime is rendered; no new telemetry field or endpoint was added. |
| Parsing daemon prompts into structured security data | Not planned. Future security facts require additive structured protocol fields; free-form text will never be a control plane. |
| Cross-distribution, Windows, or macOS GUI v2 compatibility | Out of scope. The preview target is Bazzite/Fedora 44. |

The authoritative disposition and future tracking for these items is in
[the roadmap](../ROADMAP.md#deferred-or-excluded-from-v040).

## Upgrade notes

- Existing profiles, `daemon.toml`, and `cli.toml` continue to work.
- `ui.toml` is optional and contains presentation preferences only. Deleting it resets profile
  ordering, pins, filter, and sort mode without affecting connection profiles.
- The packaged executable remains `ssh-tunnel-gtk`. GUI v2 is still built from source, but
  now supplies its own first-launch client-connection setup when `cli.toml` is missing or
  invalid.
- The production application name/ID, packaging, root-workspace integration, CI/default
  target, and retirement of `gui-gtk` require a later accepted cutover.
