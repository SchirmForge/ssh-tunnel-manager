# Release Notes - v0.1.11

**Release Date**: 2026-08-30

## Overview

Version 0.1.11 is a **stability release**. It adds no new user-facing features. The work
went into automated regression testing, continuous integration, fixing defects found along
the way, and reorganising the documentation so it describes the software that actually
exists.

The headline is that the project now has a real test suite. Before this release the
authentication flows — the most intricate and most frequently broken part of the codebase —
had only ever been tested by hand.

**Upgrade notes**: none. No configuration change, no profile format change, no API change.
Existing profiles and `cli.toml` files work unmodified.

## Key Highlights

### 🧪 Added: A two-tier test suite

**Problem**: The project had 42 unit tests, no integration tests, and no CI. Every
authentication path — key, passphrase, password, 2FA, retry, host key verification — was
verified by a human connecting to a server and watching what happened. The v0.1.10 2FA
retry fix, which took a substantial redesign of both daemon and GUI, was protected by
nothing.

**Solution**: Two tiers, split by whether a real SSH server is needed.

- **Tier 1 — hermetic** (`cargo test`): no network, no credentials, runs everywhere. Spawns
  a real daemon per test and drives its REST/SSE API through the real client. Covers health
  and info per listener mode, token missing/wrong/correct, the loopback-only HTTP rule,
  socket and directory permissions, the single-instance PID guard, and SSE connect,
  heartbeat and authentication.
- **Tier 2 — live SSH** (`make test-live`): real connections to a real server. Covers host
  key verification and refusal of a changed key, key authentication, encrypted-key
  passphrase prompting, password authentication, wrong-password and wrong-2FA-code
  re-prompting, two-factor authentication, traffic actually flowing through the forward,
  and teardown both while connected and mid-authentication.

TOTP codes are generated in-test, so 2FA is covered without a human. The generator is
verified against the RFC 6238 and RFC 2202 test vectors, so it is trustworthy even when the
live server is unavailable.

**Result**: 79 tests where there were 42, one of which was failing.

### 🔒 Added: Test isolation, and a sandbox for manual testing

**Problem**: Running `cargo test` could damage the developer's own setup. The pidfile test
called `PidFileGuard::create()`, which resolves the real
`$XDG_RUNTIME_DIR/ssh-tunnel-manager/daemon.pid` — with a daemon running the test failed,
and with none running it would create and then delete the live daemon's PID file. Two more
tests read the real `~/.config`. Worse, `scripts/test-network-modes.sh` ran
`rm -rf "$HOME/.config/ssh-tunnel-manager"`, wiping the developer's profiles.

**Solution**: Every config path already resolved through `dirs::config_dir()`, and the
socket and PID file through `dirs::runtime_dir()`, which honour `XDG_CONFIG_HOME` and
`XDG_RUNTIME_DIR`. Redirecting those two variables gives a test run its own private world —
**no production code had to change**.

- `scripts/sandbox.sh` provides this for shell scripts
- The integration harness sets them on the spawned daemon's environment rather than the test
  process's, so tests still run in parallel
- `PidFileGuard::create_at()` lets the pidfile tests use a temporary path
- `scripts/test-network-modes.sh` is rewritten on the sandbox and can no longer touch
  anything outside it

**Result**: your real configuration and any running daemon are untouched by the test suite.

### 🛠 Added: `scripts/dev-env.sh` and CI

`make sandbox` builds debug binaries, opens a sandbox, starts a daemon in any listener mode,
wires `cli.toml` to its generated token, seeds a profile per authentication type, and drops
you into a shell with `ssh-tunnel` and `ssh-tunnel-gtk` on `PATH`. Exiting tears it all
down. This is how the GTK GUI gets exercised, since that cannot be automated.

`.github/workflows/ci.yml` runs formatting, clippy with `-D warnings`, the hermetic tests
and a release build on every push. There was no CI before.

### 🐛 Fixed: Cancelling a tunnel during authentication

**Problem**: `TunnelManager::stop` held the tunnel-state write lock for its entire body,
including the wait for the tunnel task to finish. But the task needs that same lock to
record its own final status. The graceful path could therefore never succeed: every
cancellation during connect or authentication waited out the timeout and then force-aborted
the task.

**Solution**: Split into two phases. Under the lock, classify the tunnel, clear the pending
authentication request and take the shutdown and join handles; then release the lock before
signalling and waiting.

**Result**: Cancellation stops the tunnel cleanly. With the deadlock gone, the grace period
no longer has to be short enough to hide it, so it moves from 100 ms to 2 s and reaching it
now logs a warning rather than being the normal path.

### 🐛 Fixed: Potential GUI crashes

**Problem**: Six places in the GTK GUI held a `RefCell<Option<DaemonClient>>` borrow across
an `await` on a daemon request. If anything borrowed that cell while the request was in
flight — and the surrounding code borrows other cell state on the success path — the process
would panic with "already borrowed".

**Solution**: `DaemonClient` is `Clone`, so the client is now cloned out of the cell before
awaiting. `clippy::await_holding_refcell_ref` catches the pattern, and CI runs clippy with
`-D warnings`.

### 🐛 Fixed: `cargo clippy` did not compile

`profiles.len() >= 0` in a `crates/common` test is always true on a `usize`, which trips the
deny-by-default `absurd_extreme_comparisons` lint. `make clippy` had therefore never passed.
All clippy warnings across daemon, CLI, common, gui-core and gui-gtk are now clear.

### 🗑 Removed: The orphaned tray crate

`crates/tray` was absent from the workspace `members` list, so `cargo build`, `cargo test`
and clippy had never compiled it — its last commit was v0.1.6, two releases before the SSE
consolidation it depended on. It also carried a duplicate `TunnelEvent` enum and SSE parser
that `crates/common/src/sse.rs` now owns.

It is removed, along with three workspace dependencies referenced by no member crate
(`ksni`, `tokio-tungstenite`, `ashpd`). System tray support becomes a future feature to be
written against the current architecture.

### 📚 Changed: Documentation reorganised

`docs/` was a flat directory mixing release history, status, roadmap, architecture
specification, operations guides and development plans. It now separates what the system
**is** from what we **intend to do**:

- `docs/architecture/` — the specification set, with `ARCHITECTURE.md` split into
  **FUNCTIONAL_ARCHITECTURE.html** (components, data flow, configuration, API behaviour) and
  **TECHNICAL_ARCHITECTURE.html** (design decisions, crate layout, concurrency, testing).
  Both carry proper SVG diagrams and follow your light or dark theme.
- `docs/user-stories/` — **new**. 67 stories across 10 epics, numbered `US-<epic>.<n>`, each
  with acceptance criteria and the tests that cover it. Five are marked **not implemented**
  rather than omitted.
- `docs/ROADMAP.md` — **new**, extracted from PROJECT_STATUS.md and organised by horizon.

A good deal of documentation was simply wrong and has been corrected: the architecture
document described a health-monitoring loop as if it shipped (`monitor.rs` is an empty
stub), advertised four CLI commands that have never existed, documented a state file that
does not exist, and showed a profile format the code does not use.

**Roadmap change**: remote port forwarding (`ssh -R`) is **dropped, not deferred**. No use
case has come up; use OpenSSH directly. `ForwardingType::Remote` stays in the enum because
it appears in existing profile TOML. Dynamic/SOCKS remains a future, unscheduled item.

## Known Issues

- **`crates/gui-qt` does not compile** — the cxx-qt 0.8.0 bridge macro fails to parse. It is
  now excluded from `default-members`, so `cargo build`, `cargo test` and CI are unaffected.
  Use the GTK GUI.
- **60-second wait when nothing answers an authentication prompt** — partly addressed. The
  lock bug above is fixed, so explicit cancellation is now prompt. The remaining 60 seconds
  is `AUTH_RESPONSE_TIMEOUT` elapsing when no client answers and nothing cancels, which is
  the timeout working as designed. Whether 60 s is the right value is open.
- **Token in `cli-config.snippet`** — the file is `0600` but contains the token in
  plaintext. Delete it after copying.
- **Auto-reconnect is still not implemented** — the options exist and are editable, but
  nothing acts on them. The design is now decided and recorded in `docs/ROADMAP.md`.

See [KNOWN_ISSUES.md](../KNOWN_ISSUES.md) for the full list.

## For Contributors

If you work on this codebase, three things changed that affect you:

1. **`make check`** now means something — formatting, clippy with `-D warnings`, and tests
   all pass, and CI enforces it.
2. **Tests must be sandboxed.** Do not call `PidFileGuard::create()` or the
   `profile_manager` functions in a test without redirecting the environment first.
3. **A skipped live test still reports `ok`.** Run the live tier with `--nocapture`, as
   `make test-live` does, or a completely skipped run looks like a passing one.

See [DEVELOPMENT.md](../DEVELOPMENT.md#testing) for the full testing guide.

## Upgrading

```bash
# From packages
sudo dpkg -i ssh-tunnel-daemon_0.1.11-0_amd64.deb \
             ssh-tunnel-cli_0.1.11-0_amd64.deb \
             ssh-tunnel-gui-gtk_0.1.11-0_amd64.deb
systemctl --user restart ssh-tunnel-daemon

# From source
git pull && cargo build --release
```

No migration is required. Profiles, `cli.toml`, `daemon.toml` and `known_hosts` are all
read unchanged.
